# 统一工位距离与电脑特写修复

日期：2026-10-17。

## 调查结论

Loft/Floor 的电脑特写可看到手部，部分角色还有黑线和局部“撕裂”。修复前截图与独立复制场景的射线检查确认：人物手臂、身体/配饰进入了电脑特写的前景与近裁剪区域。屏幕内容本身没有损坏。

根因是座位锚点到显示器正面的水平距离不一致：

| 布局 | 原距离 | 统一后 |
| --- | --- | --- |
| 三人 / 九人 | 1.460 | 1.420 |
| Suite | 1.338 | 1.420 |
| Loft / Floor | 1.138 | 1.420 |

以上为场景单位，沿座位朝向测量，到实际显示平面为止，不是显示器支架的摆放坐标。

## 最终实现

五种布局均引用 `src/shared/workstation.js` 的 `monitorPlacement`。显示面距离为 1.42；带独立显示器组的布局使用 0.012 的面板偏移，支架组的前向距离为 1.432。

面对面工位的座位间距仍为 3.10，显示器外壳背面之间留有约 0.066 的间隙。Loft 第一盆中央绿植和 Floor 的中央绿植移到显示器列之间，避免新位置的显示器背板穿插绿植。

未采用临时隐藏人物的方案，已完全撤回相关代码。镜头距离、近裁剪参数、显示材质、人物动作、座位坐标、键盘位置和寻路障碍保持原逻辑。

## 验证

- `npm run test --workspaces=false`：38 项通过，涵盖工位规范、对坐显示器间隙、绿植净空，以及原有座位、键盘触达、寻路和任务数据测试。
- `npm run test:geometry:workstations --workspaces=false`：五种场景的实际模型共 54 台屏幕均为 1.42，无横向偏差；四种打字姿态下，屏幕及周围镜框的采样射线没有命中前景人物。全部人物保持可见。
- `npm run test:browser:computers --workspaces=false`：通过真实头像菜单测试全部 54 台电脑、主题/白板/全景/人物/俯视镜头切换、Loft/Floor 窄屏切换、默认动画过渡；人物状态不因聚焦改变，控制台无错误或警告。
- 默认构建及 Loft、Suite、Floor 独立构建通过。
- 已打开对比 Loft 与 Floor 的修复前后截图，确认手部遮挡和异常线条消失。

截图及测量报告保存在忽略目录 `.artifacts/computer-focus/`。`*-before.png` 是调整距离前的截图，`*-after.png` 是统一距离后的截图；`geometry-after.json` 为实际模型测量与遮挡检查结果。
