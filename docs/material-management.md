## 阶段二：重复家具

`src/assets/furniture/primitives.js` 提供桌面、办公椅、显示器、键盘、绿植、杯子的共享构建器，以及座位坐标到前/侧方向坐标的转换。场景家具文件保留房间、墙体、特殊装饰和摆放逻辑；旧三人/九人、套间、对坐长桌的显示器尺寸作为明确变体保留，未强行统一外观。

导航预留尺寸放在不依赖 Three.js 的 `furniture-spec.js`，供五布局和构建器共用。

- 椅子返回 `seat` 和 0.78 × 0.78 的导航预留范围。
- 桌面返回桌子平面范围和高度；桌脚/横梁仍由不同桌型摆放。
- 绿植返回地面碰撞范围；台面盆栽返回 `null`。房间布局可以保留更宽的通行预留区。
- 显示器返回实际 `screen` 网格及父坐标系中的 `mount`；屏幕正面距离继续由 `workstation.js` 规定为座位前方 1.42。屏幕不参与静态方块合批，继续注册为任务展示挂点。
- 家具构建器返回的碰撞数据是可供布局使用的契约；运行时完整障碍物集合仍以各布局现有的数据为准，包括墙体、桌子和通道预留区。

`test:browser:furniture` 与 `10c42fc` 源码生成的快照比较，覆盖 8,193 个网格实例的几何包围盒、世界变换、材质属性与 Canvas 贴图像素。测试快照在 `tests/fixtures/furniture-baseline.json`；有意更改美术后应审核并更新快照，而不是把失败直接当成无效测试。

## 阶段三：资源归属

`art.js` 的共享缓存有显式租约：`acquireArtResources()` 返回可重复调用的释放函数。共享单位盒几何体、按颜色/类型缓存的材质和它们的贴图属于缓存；同页全部租约结束时统一释放并清空，后续挂载创建新资源。共享材质和贴图应视为只读，个别屏幕换材质时必须创建私有资源。

每个 `createScene()` 在创建资源前获得租约。`src/engine/resources.js` 遍历释放场景私有平面、脸部纹理、非缓存材质、实例化网格和阴影目标，跳过缓存所有的资源。初始化失败同样执行这套清理；单个释放抛错后继续释放其他资源。任务展示层先恢复原屏幕材质并释放自己的动态纹理，再由场景处理其余资源。

人物导出每次捕获同样获取租约，最终在 `finally` 释放全部私有资源和共享租约。直接调用底层 `createCharacter()` / 家具构建器的自定义宿主也必须持有租约，并在移除根对象之前调用 `disposeSceneResources(root)`，最后释放租约；只调用 `scene.remove()` 不会释放 GPU 资源。缓存可跨场景共享，直到最后一个活跃使用者退出；它不做逐材质淘汰。

验证包括 Node 释放计数、清理失败继续执行，以及真实浏览器中两个同时存活的 WebGL 场景：关闭一个后另一个仍能渲染，兄弟场景初始化失败不误释放共享资源，最后一个退出后各共享资源只释放一次，重新挂载使用新资源。

## 阶段四：事务导出

```powershell
npm run dev
npm run export:characters
npm run export:characters -- --only=portrait,sheet
npm run export:characters -- --ids=team-00
npm run export:characters -- --only=portrait --ids=team-00
```

全量导出从空的兄弟临时目录开始，生成全部 27 个外观的三种文件。局部导出必须已有有效的完整产物，先复制旧目录，再只生成选中的外观和种类；未选中文件保留字节与清单哈希。`--ids` 接受稳定外观 ID，`--only` 接受 `portrait,sheet,model`。不接受未知或重复选择。外观变化时必须为该外观导出全部三种文件；人物集变化时必须全量导出，避免混合不同版本外观。

导出前核对浏览器与 Node 的完整人物清单；发布前重新读取临时目录，检查 PNG 头/尺寸/分块 CRC/解压数据、GLB 头/JSON/BIN、文件大小与 SHA-256，以及清单计数。输出目录使用同级锁防止并发写入。`scripts/lib/publish-directory.mjs` 优先把旧目录改名为备份，再把临时目录改名为目标；发布失败则恢复旧目录。

Windows 上目录改名遇到 `EPERM`、`EACCES` 或 `EBUSY` 时，退回到独占创建目标、复制并逐文件核对目录结构和完整字节。旧目录只有在备份复制及核对完成后才移除；旧目录部分删除失败或新产物复制失败时，先清理残留目标，再恢复完整备份。其他平台和其他错误直接进入原有失败处理。失败复制不会覆盖已存在的备份路径，回滚失败则明确报告并保留备份。

发布并非原子目录交换：改名路径有短暂缺口，Windows 复制退路还会让目标在复制完成前处于不完整状态。消费者应在导出成功返回后读取，不应把此目录当作在线更新的静态服务目录。如果进程或机器在发布中被强制终止，检查同级 `.characters-stage-*-previous` 和 `characters.lock`，确认没有导出进程后，先校验备份的格式、哈希与清单，再恢复并移除锁；中断时备份也可能尚未复制完成。此流程针对本地生成目录，尚未引入外部资产库或数据库。

清单的使用关系是当前代码的权威记录。局部更新保留未选中的旧对照图，因此其图内说明文字可能仍是先前导出时的说明；需要全部更新图内文案时完整导出。

运行时仍由 JavaScript 生成人物和家具，`publicDir: false` 保留。GLB 是包含当前模型、材质和脸部纹理的静态快照，不包含 JavaScript 驱动的完整动作、寻路和表情逻辑。
